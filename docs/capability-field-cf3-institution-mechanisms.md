# CF3 — Institution Mechanisms: Rescue Attempt After M3 Failure

Status: **COMPLETE**
CF0 result under attack: transition topology had `0` incremental static predictive cases over strong M2.

## 1. CF3 does not rescue M3 as a predictive family

That negative result survives.

For every current static case, a sufficiently rich M2 function can represent the mapping:

```text
Y = F(Actor, Environment, Institution, Resources, Demand)
```

CF3 therefore rejects the move:

```text
mechanism decomposition
→ independently necessary predictive ontology
```

## 2. But decomposition can change the next action

A model can fit an outcome while still giving a poor intervention explanation.

Consider:

```text
API unavailable to this Actor
```

Possible treatments include:

- add technical capability;
- restore network path;
- obtain eligibility/account authority;
- satisfy payment/contract requirement;
- wait for quota renewal;
- choose a substitute.

A generic interaction term can represent the current `no`, but does not by itself tell the system which relation owns the blocker.

CF3 therefore tests M3 as an **intervention/owner-localization vocabulary**, not a prediction family.

## 3. Seven conditional mechanism roles

CF3 retains seven roles only when the question activates them:

1. **allocation / access** — who can reach or receive the opportunity/resource;
2. **authority / admission** — who may commit which transition;
3. **incentive / cost** — how rewards, burden and commitments change selection;
4. **enforcement / sanction** — what makes a declared rule consequential;
5. **ownership / appropriation** — who controls or captures the effect/value;
6. **coordination / information** — how recurrent matching, sequencing and information flow are structured;
7. **recovery / exit** — what happens after failure, uncertainty, dependence or refusal.

These are diagnostic roles. A real institution may instantiate several; a given question may need only one.

## 4. Deletion consequences

Collapsing these roles can produce distinct wrong actions:

```text
access failure        → blamed on skill
missing authority     → treated as missing capability
declared rule         → treated as enforced rule
physical effect       → treated as actor-owned value
coordination failure  → treated as resource absence
no recovery           → treated as same option value as recoverable exploration
```

The CF3 matrix contains six cases where mechanism decomposition changes the intervention/owner decision even though M2 can fit the current mapping, three cases where institution vocabulary adds no value, and one conditional cost case.

## 5. The partial rescue

CF3 therefore gives `Institutional Conversion Topology` a narrower status:

> **RETAIN AS A DECISION-LOCALIZATION TOOL; REJECT AS A UNIVERSAL PREDICTIVE MODEL OR PERSISTED SCHEMA.**

This distinction matters. The useful object is often not an institution record but a compact causal sentence:

> The tool exists and the Actor can technically invoke it; the blocker is current Finance admission authority for this capital action. Adding compute or another API implementation will not change the decision.

That is exactly the Computing causal-responsibility style: enough structure to prevent the next wrong action.


Mechanism facts stay with their native owners.
