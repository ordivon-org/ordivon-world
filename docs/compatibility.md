# Compatibility

| Component | Supported value |
|---|---|
| Python | `>=3.12,<3.13` |
| Ordivon Host | `95cd5479e71281baed5a1d1c34cbfaadffe2a22f` |
| Ordivon Protocol | `420dc356cb664d75db0f34f356156baebe5843db` through Host |

| JSON Schema | Draft 2020-12 |

`uv.lock` and `pnpm-lock.yaml` are required release inputs. Compatibility claims apply only to the locked graph.

## Pre-1.0 policy

The package is experimental. Public Python names exported from `ordivon_world` are the recommended facade, but breaking changes may occur before 1.0 when accompanied by:

- a documented failure or requirement;
- a migration note;
- updated contract and live acceptance evidence;
- no reinterpretation of retained provider Receipts.

## Durable compatibility

The most important compatibility surface is not import syntax. It is the ability to reopen retained state and reconcile the same external action.

Changes must preserve or explicitly migrate:

- `PreparedWorldDispatch` fields and digest semantics;
- deterministic provider request identity;
- provider request digest verification;
- Host Dispatch and Observation identities;
- Cloudflare Receipt and Artifact references;
- UNKNOWN versus failed/rejected distinctions;
- capability-condition invalidation behavior.

## Provider compatibility

Provider-native schemas remain local to the provider. A future second provider may implement the same high-level adapter operations without sharing Cloudflare lease, R2, policy or error fields. Do not normalize provider facts that are not semantically interchangeable.

## Deployment compatibility

Cloudflare Worker identity is based on deployable Worker inputs, not the whole repository commit. A Host adapter, documentation, test or GC-controller-only change can update the repository without requiring Worker redeployment when the Worker-input digest remains unchanged.

Installed operator controllers must match source digests before live health is considered current.
