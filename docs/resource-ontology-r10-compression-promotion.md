# Resource Ontology R10 — Compression, Promotion and Foundations Closeout

## 1. R10 objective

R10 is not another ontology-expansion round. It asks which R0-R9 results deserve canonical production doctrine, which remain conditional reasoning vocabulary, which universal structures should stay rejected, and whether any reproduced correctness debt is narrow enough to fix without reopening a global architecture.

The final procedure was:

```text
freeze exact R0-R9 evidence
→ promotion matrix
→ merge/delete overlapping distinctions
→ preserve conditional relations as optional query templates
→ explicit negative doctrine
→ narrow R9P01 fix tournament
→ current probes
→ full regression / CI / canonical closeout
```

## 2. Promotion result

R9 retained 13 root distinctions. R10 compresses them into 11 canonical laws rather than preserving every historical label separately.

### L1 — Boundary-relative enrollment

Resource truth is relative to a declared actor/system boundary and exact Reality aspect; coarse Resource is an existential projection over at least one supported admissible transition witness.

Deletion consequence: Hostile/irrelevant aspects, ticker/asset identity, exact reviewed bytes and security target identities can be conflated; capability labels become self-authenticating.

Reopen condition: Reopen only if a materially different owner can make correct Resource decisions without actor boundary, aspect identity or any transition witness.

### L2 — Native truth, projected relation

Events, Claims, authority, access, quantities and domain state remain owner-native; World may join/project them but does not become their second source authority.

Deletion consequence: Historical/current truth is rewritten by a World state machine and cross-owner projections become accidental authority.

Reopen condition: Reopen only if multiple owners demonstrably cannot reconcile required shared truth and one lower owner can own it without duplicating native authority.

### L3 — Claim-bound evidence

Evidence is a provenance/method/time-bound support, contradiction, bounding or unresolved relation to an explicit Claim; Resource-level provenance alone does not establish transition/capability truth.

Deletion consequence: Missing/stale evidence becomes false truth, negative evidence disappears, and aggregator/candidate capability labels can mint current ResourceFor truth.

Reopen condition: Reopen only if a simpler representation prevents R9P01 and all five dogfood overclaims without an explicit claim-support boundary.

### L4 — History is not currentness

Historical Events/accepted Claims remain historical truth while current applicability/actionability is recomputed as-of from claim-specific clocks; there is no universal Resource current/lifecycle bit.

Deletion consequence: Later evidence leaks backward, revoked/stale facts erase history, and one lifecycle state cannot express simultaneous demand-specific projections.

Reopen condition: Reopen only if a universal state machine survives concurrent demands, independently stale claims and non-monotonic access without loss.

### L5 — Actionability and Option are downstream

Resource may exist before possessed authority/access/current demand fit; ActionableResourceFor is the demand/time projection where required current conditions hold, and Option is the selectable feasible relation.

Deletion consequence: Gated/deferred/reference resources disappear or Resource collapses into current permission/use.

Reopen condition: Reopen only if deferred acquisition, dormant/reference resources and workload-specific actionability can be represented with fewer distinctions without changing decisions.

### L6 — Feasibility is conjunctive and owner-local

Target transitions have explicit Requirements, contextual Assignments and native Constraints; feasible composition is a projection, not a global dependency graph.

Deletion consequence: Partial resources are treated as jointly sufficient or owner-local admission/reducers are duplicated by a global graph.

Reopen condition: Reopen a shared engine only after multiple materially different consumers reproduce the same missing composition executor above owner boundaries.

### L7 — Quantity only when binding

Capacity/rate/budget/stock/flow are native-unit, native-clock constraints used when they change feasibility, throughput, risk, contention, burden or recovery; no global scalar Capacity exists.

Deletion consequence: Minimum notional, slots, concurrency and review burden cease to affect feasibility; a global scalar launders incompatible units.

Reopen condition: Reopen a shared Capacity surface only when one concrete cross-owner query repeatedly needs the same quantity semantics and current owners cannot answer it by projection.

### L8 — Substitution and redundancy are contextual

Substitution derives from alternative feasible assignments for the same requirement/context; redundancy additionally requires sufficient independence against a declared disturbance and requested load.

Deletion consequence: Duplicate keys/endpoints/providers are miscounted as capacity or resilience and common-mode failure is hidden.

Reopen condition: Reopen intrinsic substitute/redundancy edges only if they remain invariant across purpose, transition, load, time and disturbance.

### L9 — Action, Effect, Outcome, Attribution, Knowledge remain separate

Action records an admitted attempt; Effect is owner-native consequence; Outcome is domain-owned evaluation; Attribution is a separate causal claim; Knowledge is an explicit reusable promotion.

Deletion consequence: Process success becomes domain success, observed outcomes get false causal credit, and every receipt/review/failure becomes promoted knowledge.

Reopen condition: Reopen only if a collapsed representation preserves exogenous effects, nested outcomes, uncertainty, counterfactual attribution and learning from failed/invalid episodes.

### L10 — Evidence acquisition is decision-scoped

Transport, target applicability, independence, coverage, reversibility/consequence and value-of-information are downstream questions of a particular Claim and decision; collect direct target evidence only when residual uncertainty can change action.

Deletion consequence: Measurement availability becomes an admission reason, weak external evidence is overgeneralized, or every claim requires expensive local replication.

Reopen condition: Reopen a universal Transfer Contract only if multiple owners repeatedly need the same persisted transport object and local projection cannot recover the decision.

### L11 — Promote semantics before machinery

A shared production seam is earned only when repeated semantics coincide with repeated missing executable responsibility, owner-local resolution fails, and moving responsibility downward reduces total system complexity.

Deletion consequence: Repeated vocabulary automatically grows registries/services and creates duplicate authority.

Reopen condition: This is itself the reopen test for any rejected global surface.

## 3. Conditional query templates

Nine surviving concepts are useful only when the question activates them. They are not universal Resource fields or durable global state.

| ID | Relation/query | Activate when |
|---|---|---|
| Q1 | Access/transport/materialization | current path/bytes/interface determine whether a supported ResourceFor can be exercised now |
| Q2 | Requirements/Assignments/Constraints | a transition needs more than one condition/resource or compatibility/admission matters |
| Q3 | CapacityFor / load | quantity/rate/budget changes feasibility or bottleneck |
| Q4 | Substitution/redundancy | alternatives are compared under a named purpose/load/disturbance |
| Q5 | Evidence coverage/absence | absence, completeness or negative claims depend on observable surfaces |
| Q6 | Evidence transport/target | source evidence is used for a different population/context/decision |
| Q7 | Reversibility/consequence/VOI | deciding whether to acquire more evidence |
| Q8 | Exact composition identity | replay/recovery/effect identity depends materially on exact members/versions |
| Q9 | Consumption accounting | stock/flow/quota/budget continuity matters for that resource family |

## 4. Explicit non-promotions

R10 closes the current foundations program with these structures still rejected:

- universal Resource lifecycle/state machine
- global persisted Resource registry/entity
- universal CapabilityManager/object
- global dependency/composition graph/engine
- global Capacity scalar/service
- global EvidenceGraph/BeliefStore/confidence service
- universal persisted Transfer Contract
- generic Outcome/Attribution service
- universal Resource value/maturity scalar
- generic cross-domain consumer/workflow platform

These are not metaphysically impossible. They are unearned production ownership. Reopen only under the extraction law: repeated semantics + repeated missing executable responsibility + owner-local failure + lower shared ownership reduces total complexity.

## 5. Claim-level provenance fix tournament

R3, R8 and R9 repeatedly reproduced one real generic World defect: a candidate/aggregator capability label could contribute full demand fit after owner identity/terms/interface were verified even though the owner verification did not attest that capability claim.

R10 compared three treatments:

| Candidate | Shape | Result |
|---|---|---|
| A — OwnerVerification.verified_capabilities | Add a tuple of owner-attested capability labels to the existing current OwnerVerification. Candidate.capabilities remains discovery/ranking vocabulary. Required capability present only in candidate but absent from current verified_capabilities yields owner-verification-required, not not-fit and not consumable-now. | correctness=PASS; authority=PASS: owner-native current verification remains the claim source; newObjects=0; risk=Does not represent every possible multi-source capability proof; deliberately narrow to current generic discovery pipeline. |
| B — CapabilityEvidence object | Create a new claim/evidence dataclass passed to evaluate_resource, with resource_id/capability/source/time/evidence refs. | correctness=PASS; authority=PASS; newObjects=1; risk=Over-generalizes R9P01 into a new evidence object before a second executable consumer needs it; starts rebuilding R8 research ontology in production. |
| C — Capability proof inside DiscoveryEvidence/ResourceCandidate | Annotate discovery provenance/candidate capabilities with proof refs and let evaluator infer verified capability from candidate provenance. | correctness=FAIL/AMBIG; authority=FAIL: discovery/aggregator plane can become semantic truth owner; newObjects=0; risk=Reintroduces the exact R3/R8 provenance laundering that R9P01 falsified. |

Winner: **A — `OwnerVerification.verified_capabilities`**.

Why A wins:

```text
candidate.capabilities
    = discovery/ranking hypotheses

current OwnerVerification.verified_capabilities
    = owner-attested capability claims used by the generic demand-fit projection
```

If a required capability appears only in candidate discovery vocabulary, current evaluation fails closed into `owner-verification-required` with `required-capabilities-not-owner-attested:<capability>`. A stale owner attestation contributes neither required nor preferred fit. Explicit owner terms/permission blocks take precedence over capability verification work.

This adds no new service, registry, global Claim object or CapabilityManager.

## 6. R10 current probes

### R10P01 — fixed

The exact R9 laundering shape was replayed after the code change:

```text
owner evidence: identity / terms / interface
candidate label: cap:x
owner verified_capabilities: empty
current demand requires: cap:x
```

Result:

```text
decision      owner-verification-required
demandFit     0.0
preferredFit  0.0
reason         required-capabilities-not-owner-attested:cap:x
```

Adding a current owner attestation for `cap:x` returns `consumable-now` and `demandFit=1.0`.

Verdict: `FIXED_NARROW_WORLD_LOCAL`.

### R10P02 — intentionally unimplemented

The generic per-resource evaluator still cannot combine Resource A(`cap:a`) and Resource B(`cap:b`) into one joint satisfaction proof for a demand requiring both.

Verdict: `INTENTIONALLY_UNIMPLEMENTED_GENERIC_COMPOSITION`.

Reason: Finance, Game, Studio, Security and Human already own their real conjunction/reducer/admission semantics; no repeated shared executable gap earns a World CompositionEngine.

Reopen: only when multiple materially different current consumers fail because no owner-local or demand-scoped composition projection can answer the same missing responsibility.

### R10P03 — intentionally absent

`ResourceCandidate`, `ConsumerDemand` and `ResourceEvaluation` still have no first-class universal `capacity/amount/stock/flow/rate/quota/concurrency/budget` coordinate.

Verdict: `INTENTIONALLY_ABSENT_GLOBAL_CAPACITY`.

Reason: quantities matter, but owner-native units, clocks and recovery semantics differ. A global Capacity service is not a current product requirement.

## 7. Canonical doctrine replacement

R10 rewrites `docs/resource-option-capability-model.md` from the earlier near-linear Resource→Actionable→Option→Capability→Effect→Knowledge story into the thinner canonical topology:

```text
owner-native Reality / truth
→ contextual Resource / Actionability / Option projection
→ bounded Requirements / Assignments / Constraints
→ Decision / Action
→ owner-native Effect
→ domain Outcome
→ Attribution if supported
→ Knowledge promotion if earned
```

The old “five useful stocks”, near-linear lifecycle language and implicit global state intuition are removed from canonical doctrine. R0-R9 preserve the research history that produced the new compression.

## 8. Operational discovery alignment

`docs/resource-opportunity-flywheel.md` now states that current matching owner verification must also attest every required capability used by generic demand fit. This aligns the operational board with the canonical claim-bound evidence law.

The opportunity board remains a planning surface. It does not become the ontology.

## 9. Persistence and ownership conclusion

R10's final persistence rule is:

> Persist owner-native history where consequence identity, recovery, audit or later semantic promotion requires it. Recompute Resource, Actionability, Option and planning composition when current owner evidence can answer the question again.

World therefore remains a narrow cross-owner projection/effect boundary rather than a database of all Resource truth.

## 10. Final foundations result

The R0-R10 program started by asking what Resources Ordivon has and how Resources become capability. It ends with a thinner result:

> **Keep Reality truth with the owner that can reconcile it. Treat Resource, Actionability, Option and conditional ecology concepts as context-bound supported relations over that truth. Require explicit claim-bound evidence for semantic transition claims. Compose through explicit requirements and native constraints. Keep Decision/Action, Effect, domain Outcome, Attribution and Knowledge promotion separate. Promote shared machinery only after multiple materially different consumers reproduce the same missing executable responsibility above owner boundaries.**

The major outcome is not a bigger ontology. It is a smaller semantic waist backed by a much larger falsification record.
