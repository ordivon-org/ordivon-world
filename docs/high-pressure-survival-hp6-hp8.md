# High-Pressure Survival HP6–HP8

HP6–HP8 finish the current World survival epoch. The purpose was not to complete numbered stages. Each stage first had to prove a distinct falsifier; a stage that could not add information would have been skipped. The final result is another contraction: historical knowledge is separated from current authority, mixed failure pressure does not force a global coordinator, and research-only executable path/capability surfaces leave the product package.

## HP6 — Research / Knowledge GC

Before HP6, eight W4/W5/Sense–Connect–Act studies still appeared in `docs/` as active or current research even though the lines had already closed. The active Markdown surface contained 40 files and about 361 KB, and `world-sense-connect-act.md` had no inbound current link despite `lifecycle: active`. This was not harmless history: current retrieval could surface stale lifecycle labels as present frontier truth.

HP6 preserved the full studies but moved them to [`archive/research/`](archive/research/) with `historical-research` lifecycle. Their current laws, counterexample locators and explicit reopening condition were compressed into [`research-closeouts.md`](research-closeouts.md). `authority.md` now names that compact file as the only current authority for the closed W4/W5/Sense–Connect–Act lines.

A deterministic retrieval A/B asked nine current-law questions covering Presence, discovery/authority, mixed UNKNOWN recovery, pre/post-admission execution mobility, cognition binding, Browser integrity, research status and provider-health ownership. With the same current product corpus around both candidates:

```text
full historical research corpus   190,984 bytes / 814 chunks → 7 / 9
minimal current closeout corpus     75,900 bytes / 163 chunks → 9 / 9
```

The larger corpus failed the research-status query because stale `active/current-research` labels outranked the actual closeout. The compact current surface used roughly 60% fewer retrieval bytes and recovered every tested law. Two attempted fresh-Provider structured A/B Runs were intentionally not counted because the Provider content was truncated before valid JSON could be parsed; HP6 did not convert an evaluation-channel failure into a knowledge verdict.

The surviving rule is:

> **Historical research is evidence, not current authority.**

Unique experiment narratives and immutable receipts remain available. They do not compete with current product truth.

## HP7 — Mixed Chaos Court

HP7 first audited whether a new chaos framework could reveal a failure class not already represented by current tests. The repository already had strong mixed surfaces: eighteen concurrent Resource/Message/Entity trajectories with six commit-after-response-loss UNKNOWN cases, and one Host Task containing Provider UNKNOWN + Resource prepared + Message delivered + Entity materialized across a Host checkpoint and fresh inspection.

HP7 therefore did not create a `ChaosManager`. It repeatedly composed the existing high-value failure classes. Twelve rounds with different Python hash seeds shuffled eight tests per round:

- 18-way concurrent cross-World trajectories;
- same-Task four-family inspection after Host checkpoint;
- independent second Provider UNKNOWN reconciliation after Host restart;
- Browser fresh-Host bundle recovery;
- Resource, Message and Entity `NOT_COMMITTED` release rules;
- Provider capability-condition drift before external dispatch.

All 96 invocations passed. No duplicate consequence, blind retry, cross-family authority promotion, global rollback requirement or global World head appeared.

The surviving rule is:

> **Mixed chaos that still converges through typed owner journals does not justify global coordination state.**

The useful coordination primitives remain exact semantic identity, Host revision fencing, family-owned UNKNOWN/reconciliation and owner-native retry proof.

## HP8 — Minimal World Tournament

HP4 had already demoted `ForeignEgressCapability` and `EffectPathQuery` from the default facade because fresh-Agent trials did not show a decision advantage. HP6 then preserved their useful laws and counterexamples in the historical research system. HP8 asked the stronger question: why should their executable Python modules, tests and packaged contracts still exist at all?

A final cross-repository scan found no production/runtime consumer. One Computing research fixture retained historical World schema paths/digests; that is historical evidence, not an independent product consumer and is deliberately not rewritten by World.

The Minimal World candidate therefore deleted:

```text
src/ordivon_world/foreign_egress.py                     352 LOC
src/ordivon_world/effect_paths.py                       422 LOC
tests/test_foreign_egress.py
tests/test_effect_paths.py
foreign-egress-capability.schema.json
foreign-egress-capability-reference.schema.json
effect-path-query.schema.json
```

The package changed from:

```text
Python source files       20 → 18
production Python LOC   5891 → 5112
Python test files          22 → 20
Python tests              139 → 121
packaged Schemas           28 → 25
root facade                14 → 14
```

The root facade did not shrink because these surfaces were already explicit imports. HP8 removed their hidden maintenance, compatibility and contract burden rather than performing another cosmetic export edit.

The candidate then passed the complete portable acceptance gate: all 121 remaining Python product/compatibility tests, all 29 Cloudflare TypeScript tests, all Provider controller/policy/operations checks, network gates, dependency/docs gates and the isolated wheel with exactly 25 packaged Schemas. The exact HP7 96-invocation chaos mix was then replayed against Minimal World and passed 12/12 rounds again.

Therefore the deletion is stronger than the earlier HP4 demotion. The laws survive; the product implementation does not.

## What HP8 deliberately did not delete

Minimality is owner-correctness plus maintenance cost, not the smallest file count at any price.

- `TraceContext` remains a tiny legacy decode/round-trip mechanic because retained pre-HP5 dispatches may contain it; new work does not author or propagate it.
- `providers/cloudflare/` remains provider-owned and extractable but currently co-located because HP5 found no operational reason to pay a repository split cost.
- the former `modules/network-observation` / `ordivon-vpn` handoff is complete: Workstation now proves isolated namespace, key/profile authority, transactional key materialization, and cleanup invariants, so World no longer retains that local actuator.
- Host resolved the 9→34 dependency-graph packaging pressure by separating the MCP server SDK from Host core dependencies; World can consume the narrow base distribution without vendoring or copying Host.
- Windows immutable external-input portability remains Runtime-owned.
- the Harness no-Tool correction failure remains Harness-owned.

Those are owner handoffs, not unfinished HP stages.

## Final surviving World production boundary

After HP0–HP8, the strongest World core is:

1. language-neutral Resource, Message and Entity cross-owner semantic contracts;
2. owner-bound external-effect preparation and exact provider/consequence binding;
3. durable UNKNOWN plus exact-original reconciliation after a possible consequence;
4. family-native `NOT_COMMITTED` retry evidence where the destination can prove it;
5. bounded `WorldTaskInspector` projection with no action-authority promotion or body dump;
6. narrow `WorldObservation.availableAt` provenance where provider time and Host admission cannot reconstruct first World availability;
7. Browser Receipt ↔ ArtifactRef ↔ bytes ↔ Manifest integrity;
8. owner-native Provider/network truth, with World aggregating or binding rather than taking over physical control.

World still does **not** need a global World Manager, Presence registry, Capability registry, automatic router/ranker, generic Interaction, distributed transaction/rollback layer, execution migration manager, provider broker or network control plane.

## End of the HP series

HP0–HP8 are closed for the current evidence. There is no HP9 backlog. A deleted or rejected surface may return only after a named current workload reproduces a failure that the retained World core plus Host, Runtime, Provider, Workstation or domain owner cannot own more cleanly.

The next World work is therefore demand-triggered experimentation, not another foundation stage.
