# Edge Research Route — Placement and External Continuity

## Route change

The previous route treated remote Node identity and lifecycle as the long-term
Agent-native center. The revised route treats those objects as a useful
hypothesis and moves the core research question upward:

> How does an open Task obtain, bind, replace, parallelize, and release mature
> external execution bodies while preserving Effect identity, uncertainty,
> evidence, and continuity?

## E0 — Preserve operational truth

Retain and harden the current Cloudflare Fetch/Browser/R2 provider. Production
reliability is real value and is not invalidated by the conceptual correction.

Non-goals:

- no provider router;
- no general Sandbox;
- no expansion of local-unshare;
- no persistent Node platform.

## E1 — Host-consumable external Effect backend

Use one real Host workload and bind:

```text
Task → Attempt → Effect → Dispatch
→ Edge provider request
→ provider execution identity
→ pending / committed Receipt
→ Artifact and Observation provenance
```

Inject response loss, stale execution, ambiguous commit, policy change, and Host
restart. Prove reconciliation before redispatch.

## E2 — Placement Requirement field derivation

Use two materially different workloads:

1. dynamic Web research escalating from Fetch to Browser to programmable
   Sandbox;
2. disposable software execution requiring writable state, dependencies, tests,
   and Artifact export.

Start with a broad field inventory, then delete fields. Retain only fields whose
removal causes attribution, recovery, consequence, cost, or explanation failure
in both workloads.

## E3 — Cross-provider continuation

Continue one Task across two external providers without loading the original
conversation or cloning a complete machine. Bind minimum sufficient inputs and
measure:

- duplicated and lost work;
- bytes of reconstruction state;
- recovery time;
- Artifact provenance completeness;
- unexplained provider-specific state;
- residual objects.

## E4 — Multi-body branch and join

Run heterogeneous parallel Attempts and join their Artifacts into one Task while
preserving separate provider, body, path, policy, and execution provenance.

## E5 — Persistent presence falsification

Test callbacks, long-lived sessions, devices, and asynchronous roles. First try
to model continuity using Task identity, participant role, service identity,
and provider objects. Introduce persistent Agent presence only if deletion
causes a demonstrated cross-workload failure.

## Decision outcomes

- **promote** compact Placement/Binding/continuation semantics;
- **absorb** them into Host/provider adapters if no independent layer is needed;
- **freeze** Node lifecycle as a reference experiment;
- **delete** misleading identity or lifecycle abstractions;
- **retain** Cloudflare production capability independently of research outcome.
