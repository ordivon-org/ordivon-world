# 1. Research question

WDF1 froze only a typed modal claim grammar and exported counterfactual alternative generation as its most upstream unresolved interface. WDF2-A therefore does **not** ask which established counterfactual theory is correct.

It asks a more primitive question:

> **What work is the word `counterfactual` currently doing across Ordivon and the external literature, which distinctions are being silently collapsed, and what hidden commitments are already required before Lewisian similarity, Stalnaker selection, SCM surgery, interventionism, law-relative semantics, powers accounts or plural semantics can even be compared fairly?**

The main finding is that the primitive-looking phrase:

```text
what if A?
```

is radically under-specified.

A usable counterfactual claim requires at least some answer to:

```text
anchor / comparison point
antecedent alteration
subject / target correspondence
preservation / invariance profile
alternative generation or selection
consequent evaluation
modal force
model / Reality truth role
```

This is a **diagnostic decomposition**, not a new Reality ontology.

# 3. Current Ordivon use inventory

A repository-wide current-use search over doctrine/research finds `counterfactual`, `intervention`, `alternative`, rule-change and hold-fixed language concentrated in research and doctrine rather than in production `src` primitives. This is an important positive result: World has **not** prematurely materialized a universal Counterfactual object or service.

The current uses fall into at least eight families.

## 3.1 Capability diagnosis

Capability doctrine asks questions such as:

```text
What if the physical path changed?
What if authority changed?
What if support/tool was removed?
What if Actor assignment changed?
```

The aim is diagnosis of what currently enables or blocks attainment.

## 3.2 Institutional diagnosis

Current doctrine retains Institution as a query-activated causal role where changing a durable rule, authority, ownership, enforcement or recovery process changes the relevant counterfactual.

This is already evidence that:

```text
change physical condition
!=
change constitutive/institutional rule
```

## 3.3 Causal identification and intervention

Capability-field work uses counterfactuals to distinguish association, exposure effect, mechanism and intervention. It explicitly warns that a successful action/effect does not by itself identify causal contribution.

## 3.4 Resource attribution

Resource research uses missing counterfactual benchmarks to block claims such as Agent alpha or marginal value-added. A realized favorable outcome is not equivalent to a causal value claim.

## 3.5 Redundancy / substitution

Resource research compares alternative feasible assignments under a named purpose/load/disturbance. Here `alternative` is not yet a counterfactual world; it can simply denote another current assignment candidate.

## 3.6 Policy / control

WDF1-E uses policy alternatives, strategy alternatives and intervention operators for control questions. Some are selectable future actions; some are model surgeries. They are not one relation.

## 3.7 Probability / chance

WDF1-F separates sample support, statistical or credal probability, transition kernels and objective chance candidates. Counterfactual probability is therefore not allowed to inherit an untyped `P`.

## 3.8 Law / disposition / causal grounding

WDF1-A/G identify a dependency knot:

```text
law            ↔ counterfactual support
disposition    ↔ counterfactual manifestation
cause          ↔ counterfactual difference
cause          ↔ intervention
```

WDF2-A must expose the knot without claiming that any one arrow is a reduction.

# 4. First deep result — `counterfactual` is not `counter-to-fact`

The external literature itself makes the terminology unstable. Philosophical use commonly includes subjunctive conditionals whose antecedent need not be false. Therefore:

```text
Counterfactual != FalseAntecedentConditional
```

and:

```text
AntecedentFalseAtAnchor
```

is a possible feature of a counterfactual query, not its defining essence.

For World research this matters because many planning/control claims are prospective:

```text
If policy A were chosen, outcome Y would ...
```

The antecedent may still become actual.

A foundation that defines counterfactual as `known false antecedent` would incorrectly exclude planning, diagnosis under unsettled facts and some scientific uses.

---

# 5. `Counterfactual` vs `hypothetical`

`Hypothetical` is broader.

A hypothetical can be any reasoning episode in which a premise/scenario is provisionally supposed:

```text
Suppose load doubles.
Assume Euclidean geometry.
Imagine the user has another credential.
Consider a market with no transaction costs.
```

It need not by itself specify:

- an anchor scenario;
- which facts are preserved;
- a relevance ordering among alternatives;
- an identity correspondence;
- a `would`-like consequence relation.

Therefore:

```text
Counterfactual ⊂? HypotheticalReasoning
```

is at most a useful discourse-level inclusion, not an ontological identity.

WDF2-A uses the following operational distinction:

```text
Hypothetical:
  reason under a supposed premise/scenario.

Counterfactual claim:
  evaluate a consequent relative to an antecedent-indexed departure
  from an anchor under some preservation/selection/evaluation regime.
```

This distinction is intentionally semantics-neutral.

---

# 6. `Counterfactual` vs bare `possibility`

A possibility claim asks whether at least one admissible alternative satisfies a target relative to a typed modal base.

A counterfactual asks what follows under a particular antecedent-indexed alteration/selection.

Thus:

```text
Possible(B)
```

is not equivalent to:

```text
If A were the case, B would be the case.
```

Even if `B` is possible, the relevant A-alternatives may all be non-B.

Likewise, a counterfactual can be true even when many nonselected possible A-alternatives make B false.

So:

```text
CounterfactualTruth != BareExistentialModalSupport
```

and WDF1's modal alternative grammar remains necessary but insufficient.

---

# 7. `Alternative` vs `counterfactual alternative`

`Alternative` is the most generic term in the current corpus.

It can mean:

```text
another current route
another feasible resource assignment
another policy
another state
another trajectory
another epistemically live explanation
another model
another possible world/history
```

A `counterfactual alternative` is narrower: it is admitted/generated/selected **for an antecedent-indexed comparison**.

Therefore:

```text
Alternative != CounterfactualAlternative
CounterfactualAlternative != AnyLogicallyDescribableAlternative
```

The second firewall was already earned in WDF1-B and survives WDF2-A intact.

---

# 8. `Would` vs `could` / `might`

Natural language and formal theories do not license a universal reduction of `would` and `could/might` to one fixed quantifier pair.

Still, their roles are different enough that World must not collapse them.

A useful semantics-neutral diagnostic is:

```text
would:
  claims sufficient stability/settlement of the consequent
  over whatever alternatives the chosen semantics treats as relevant.

could/might:
  claims compatible availability/non-exclusion of the consequent
  in at least some relevant sense.
```

But WDF2-A does **not** freeze:

```text
might(A,C) = not would(A,not C)
```

because the duality is contested in the literature.

New firewall:

```text
WouldCounterfactual != Could/MightCounterfactual
```

without yet fixing their exact logic.

---

# 9. `Intervention` vs counterfactual

WDF1 already established:

```text
AgentAction != CausalIntervention
Control != Intervention
```

WDF2-A sharpens the relation further.

A formal SCM-style intervention is a **specific alteration operator relative to a causal model**: selected determining relations are replaced/overridden while specified other structure remains invariant.

A counterfactual need not be interventionist in this sense.

Examples:

```text
If the match had been struck ...
If Caesar had commanded in another era ...
If the law of the institution had been different ...
If this token had received treatment ...
```

Some of these can be represented using interventions, but the representation is an additional theoretical move.

Hence:

```text
InterventionCounterfactual ⊂ CounterfactualFamily
```

may hold inside particular formalisms, but:

```text
Counterfactual = Intervention
```

is rejected as a foundation-level identity.

Likewise:

```text
PhysicalManipulation != FormalIntervention
```

unless the physical manipulation realizes the model's required isolation/surgery conditions closely enough for the target query.

# 10. Antecedent alteration is typed

The phrase `make A true` hides fundamentally different operations.

WDF2-A identifies at least the following alteration families.

## 10.1 Value/state alteration

```text
X := x'
```

with determining mechanism treated as otherwise fixed.

Example: different initial velocity under the same dynamics.

## 10.2 Action/choice alteration

```text
Actor chooses a' rather than a
```

with policy-generating mechanism potentially held fixed or not, depending on query.

## 10.3 Exogenous/background alteration

Change a contextual input/disturbance while endogenous mechanisms remain fixed.

## 10.4 Mechanism/function alteration

Replace how a variable/process is generated:

```text
F_X -> F'_X
```

This is not a mere value change.

## 10.5 Policy alteration

Replace a policy/strategy mapping:

```text
π -> π'
```

rather than forcing one isolated action token.

## 10.6 Rule/institution alteration

Change a durable constitutive/regulative rule that alters statuses, authority, admissible transitions, incentives, ownership, enforcement or recovery.

This can change the **meaning or existence** of downstream institutional variables, not merely their values.

## 10.7 Boundary/interface alteration

Change what counts as inside/outside the modeled system, which interfaces are available, or which owner/environment relation is exposed.

## 10.8 Representation/model alteration

Change variables, granularity, graph, equations, ontology or abstraction while Reality may be unchanged.

This is a counterfactual **about a model/representation** unless independently grounded as a Reality alteration.

## 10.9 Nomological alteration

Ask what follows if a law/nomological structure differs.

This cannot simultaneously assume all actual laws are invariant.

## 10.10 Semantic/conventional alteration

Ask what follows if linguistic/mathematical/institutional conventions are changed.

Some apparently impossible antecedents may shift into this class rather than requiring impossible Reality worlds.

### Alteration firewall

```text
ValueChange
!= ActionChange
!= MechanismChange
!= PolicyChange
!= Rule/ConstitutionChange
!= BoundaryChange
!= ModelRevision
!= LawChange
!= ConventionChange
```

They can sometimes be represented in a common formal language, but common representation does not imply common truthmaker or same preservation obligations.

# 11. `Hold fixed` is not one operation

The current phrase `all else equal` is too weak for foundations.

Possible invariance targets include:

```text
logical/semantic relations
nomological structure
causal graph/structural mechanisms
particular background facts
exogenous token state
past history
boundary conditions
initial conditions
institutional rules
constitutive criteria
Actor identity
policy/strategy
observation/evidence state
random coupling / latent seed
scale/grain
model variable meanings
```

Different counterfactuals preserve different subsets.

Therefore:

```text
InvariantBackground != AllActualFactsExceptAntecedent
```

because keeping every other actual fact fixed often blocks the downstream consequences that the counterfactual is trying to evaluate.

And:

```text
Invariance != NoChange
```

because an invariant can itself be a relation/rule that permits many downstream values to change.

---

# 12. `Ceteris paribus` vs exact invariance

`Ceteris paribus` often functions as a defeasible, context-sensitive qualification:

```text
other relevant things being equal/normal
```

It does not automatically name a complete exact set of frozen variables.

It can encode:

- idealization;
- defeater exclusion;
- normal background conditions;
- domain-specific exception tolerance;
- pragmatic relevance.

Thus:

```text
CeterisParibus != ExactHoldFixedSet
```

and a theory that silently compiles the former into the latter has added substantive assumptions.

---

# 13. `Nearest`, `similar`, `minimal change`

These three expressions are frequently treated as interchangeable. WDF2-A rejects that collapse.

## 13.1 Similarity

Similarity requires respects/dimensions and some aggregation or priority rule.

```text
similar in what respects?
```

is not optional.

## 13.2 Nearest

`Nearest` is the result of an ordering/selection relation. It need not come from a metric and need not be unique.

## 13.3 Minimal change

`Minimal change` requires a cost/order over changes.

Possible change costs include:

```text
number of changed variables
magnitude of value changes
law violations
causal-parent overrides
history divergence
institutional rule edits
semantic/constitutive disruption
energy/resource cost
policy complexity
```

These induce different selections.

Therefore:

```text
Nearest != MostSimilar by definition
MostSimilar != MinimalNumberOfChangedFacts
MinimalChange != MinimalHammingDistance
```

unless a specific theory supplies those identifications.

### Hidden issue: priority lexicography

Even if all dimensions are named, one must still decide tradeoffs. Lewis's later similarity weighting is one influential example, but its existence demonstrates rather than eliminates the hidden-priority problem.

---

# 14. Counterfactuals are generally non-monotonic in antecedent/background handling

Adding a new antecedent condition can flip a counterfactual judgment:

```text
If match struck -> lights
If match struck AND no oxygen -> does not light
```

Therefore a naive monotone rule:

```text
A -> C
therefore A & B -> C
```

is unsafe for counterfactual reasoning.

This matters for Ordivon because a WorkingSet or policy context can add a new constraint/condition and thereby change which alternatives are relevant rather than merely narrow an already fixed set.

The hidden assumption is:

```text
AntecedentStrengtheningPreservesSelection
```

which WDF2-A rejects by default.

---

# 15. Identity / continuity is a first-class counterfactual problem

A counterfactual usually compares something described as `the same` object, person, institution, program or system under alteration.

But WDF0 already froze:

```text
IdentifierEquality != OntologicalIdentity
Same_X != Same_Y without criterion
```

Hence WDF2 cannot import a universal transworld identity rule.

Examples:

```text
same person with different action
same program with different input
same service after implementation replacement
same institution after constitution change
same physical system after boundary redefinition
same variable after model revision
```

are not governed by one criterion.

A counterfactual claim therefore needs either:

```text
identity criterion
```

or a weaker:

```text
correspondence / counterpart / tracking criterion
```

appropriate to the domain.

New firewall:

```text
CounterfactualCorrespondence != UniversalTransworldIdentity
```

---

# 16. Rule change is not just a physical variable change

Consider:

```text
actual:
  role R lacks authorization A under rule set K

counterfactual 1:
  same K, different credential/state -> A

counterfactual 2:
  K itself changes so role R is now authorized without that credential
```

These are not the same surgery.

In the second case, changing K can alter:

- which states are legal;
- what `authorization` means;
- which transitions exist;
- who owns a right;
- which enforcement mechanism applies.

So:

```text
InstitutionalRuleChange != OrdinaryEndogenousVariableAssignment
```

unless a representation explicitly models rules as changeable variables **and** preserves their constitutive semantics correctly.

This is a central cross-domain pressure on pure value-intervention architectures.

---

# 17. Mechanism change is not value intervention

Similarly:

```text
set output X=x
```

is not the same as:

```text
replace function F_X with F'_X
```

The latter changes how X responds across a family of contexts.

For Agent systems:

```text
one action token changed
!=
policy changed
!=
planner changed
!=
provider/model changed
```

For software:

```text
input changed
!=
configuration changed
!=
code patched
!=
runtime semantics changed
```

For physical models:

```text
initial state changed
!=
boundary condition changed
!=
dynamics changed
!=
law candidate changed
```

Any counterfactual architecture that provides only value assignment is therefore at risk of silently encoding mechanism/rule change through ad hoc variables.

---

# 18. Backtracking vs non-backtracking is hidden

When an antecedent differs from actuality, should earlier conditions be altered to explain how the antecedent came about, or should history be held fixed up to a localized departure?

This is a general form of the classic backtracking problem.

For example:

```text
If the server had been healthy at t2 ...
```

could mean:

```text
A. minimally override health at t2 and propagate forward
B. infer an earlier repair/configuration/network history that would naturally make it healthy at t2
```

These can yield different downstream consequences.

Therefore the query needs a temporal/causal direction convention or generator that decides whether antecedent accommodation may revise the past/upstream causes.

New hidden parameter:

```text
BacktrackingPolicy
```

No universal default is frozen here.

---

# 19. Preemption shows that simple but-for difference is insufficient

Classic preemption cases demonstrate that an event can be a plausible actual cause even when:

```text
if C had not occurred, E would still have occurred
```

because a backup process would have produced E.

Thus:

```text
ActualCause(C,E) != simple CounterfactualDependence(E on C)
```

This does not settle causation; it constrains WDF2.

A counterfactual architecture designed only around negating one candidate cause and checking whether the effect disappears will be too weak for later WDF3 causal comparison.

WDF2 therefore must preserve the ability to express:

- contingency-sensitive alterations;
- backup/preempted processes;
- pathway/mechanism differences;
- prevention/omission contrasts;
- overdetermination.

---

# 20. Prevention and omission are not generic negative events

`A prevented E` and `omission O caused E` require more than representing `not-A` or `not-event` as Boolean values.

They often depend on:

- an expected/default/normal process;
- a candidate causal pathway;
- responsibility/agency scope;
- time window;
- available alternatives;
- whether absence is itself a variable/event in the model;
- institutional duty or norm in responsibility contexts.

Therefore:

```text
Prevention != NegativeCause by syntax
Omission != BooleanFalseEvent by syntax
```

WDF2-A does not solve these cases; it reserves the structural distinctions needed to test them later.

---

# 21. Impossible antecedents cannot be deleted from the research domain

Counterpossibles expose a live foundational divide.

Standard possible-world style treatments often yield vacuous truth when no possible antecedent-world exists. Nonvacuist accounts introduce impossible worlds or other hyperintensional/semantic machinery to allow nontrivial evaluation.

WDF2-A therefore cannot freeze:

```text
Antecedent must be objectively possible
```

as a universal precondition.

Instead, impossible antecedents become a typed residual:

```text
logical impossibility
nomological impossibility
metaphysical impossibility candidate
constitutive impossibility under current rules
model-internal inconsistency
semantic/conventional shift
unknown possibility status
```

These may require different treatment.

New firewall:

```text
ImpossibleAntecedent != OneUniformCase
```

# 22. Probabilistic counterfactuals require more than conditional probability

WDF1-F already prevents collapse of probability meanings. WDF2-A adds a three-way separation familiar from causal modeling:

```text
P(Y | X=x)                 observational conditional
P(Y | do(X=x))             interventional distribution
P(Y_x | evidence/context)  counterfactual distribution
```

These are not interchangeable by default.

The deepest hidden assumption in individual/token-level probabilistic counterfactuals is **cross-alternative coupling**.

To ask:

```text
What would this same unit/token have done under x instead?
```

one must specify which latent/background facts are shared across actuality and the altered scenario.

In deterministic SCM language this is often represented by holding exogenous variables fixed after abduction. In nondeterministic/probabilistic generalizations, the coupling question becomes explicit rather than disappearing.

Therefore:

```text
CounterfactualProbability != ConditionalProbability
CounterfactualProbability != InterventionalDistribution
ProbabilityMeasure != CrossWorld/AcrossAlternativeCoupling
```

This is a major WDF2 residual.

---

# 23. Structural model revision creates counterfactuals outside fixed-model semantics

A fixed model can evaluate only antecedents expressible within its variable/structural vocabulary.

But Ordivon's WDF0 structural revisability requires changes to:

```text
variables
relations
boundaries
mechanisms
scales
categories
```

when evidence demands them.

Therefore a general World counterfactual architecture must distinguish:

```text
WithinModelCounterfactual
```

from:

```text
CounterfactualAboutModelStructure
```

and from:

```text
ModelRevisionNeededBeforeCounterfactualCanBeAsked
```

Example:

```text
What if this institution had a kind of right/status absent from the current ontology?
```

cannot always be represented as setting an existing variable to a new value without changing the model's semantics.

New firewall:

```text
CounterfactualEvaluation != StructuralModelRevision
```

while permitting model revision to be a prerequisite for a valid counterfactual evaluation.

# 24. Model counterfactual vs Reality counterfactual

WDF0/WDF1 prohibit upgrading model alternatives into Reality truth.

A simulation can answer:

```text
Under model M, if A were imposed, C would follow.
```

This does not automatically establish:

```text
In Reality, if A were the case, C would follow.
```

The latter requires evidence that the model's variables, mechanisms, invariances and transport assumptions are adequate for the target claim.

Therefore every strong counterfactual claim should retain a truth-role distinction such as:

```text
formal/model-implied
empirically identified under assumptions
Reality-facing but defeasible
purely hypothetical/exploratory
```

No production schema is frozen, but the firewall is mandatory:

```text
ModelCounterfactual != RealityCounterfactualTruth
```

# 25. A semantics-neutral diagnostic signature

WDF2-A needs a way to expose hidden assumptions without choosing an ontology. The smallest useful diagnostic signature currently found is:

```text
CFQuery =
  Anchor
  + AntecedentAlteration
  + Target/Consequent
  + PreservationProfile
  + AlternativeGeneratorOrSelector
  + ModalForce
  + IdentityOrCorrespondenceCriterion
  + TruthRole/ModelProvenance
  + Probability/CouplingRole when relevant
```

Optional but frequently necessary coordinates include:

```text
Time/Horizon
BacktrackingPolicy
Scale/Grain
Boundary/SystemCriterion
Actor/Policy
Institution/RuleSet
Normality/Default
Evidence/Currentness
```

This signature is **not** a frozen object model and not a claim that every natural-language counterfactual consciously specifies all fields. It is an audit checklist for the assumptions a theory or context must settle somehow.

# 26. Matched cross-domain case set

WDF2-A constructs a first matched set without selecting a semantics. Its purpose is to expose which distinctions any candidate architecture must preserve.

## Case P1 — physical value change

Actual/model anchor:

```text
ball launched at velocity v under dynamics D
```

Counterfactual:

```text
if v were v', where would it land?
```

Likely preservation candidate:

```text
D fixed
boundary fixed
object identity criterion fixed
```

Pressure: ordinary value alteration.

## Case P2 — physical mechanism/law change

```text
if drag law/mechanism differed, where would the ball land?
```

Cannot use the same preservation profile as P1 because D is now altered.

Pressure:

```text
value alteration != mechanism/nomological alteration
```

## Case S1 — software input change

```text
same program/version, different input x'
```

Pressure: execution counterfactual with code/runtime semantics held fixed.

## Case S2 — software code patch

```text
same input, patched algorithm/version
```

Pressure: mechanism change; `same program` requires version/identity criterion.

## Case S3 — language/runtime semantics change

```text
what if integer overflow semantics/language rule differed?
```

Pressure: constitutive/semantic change, not normal program-state variation.

## Case I1 — institutional state change under fixed rules

```text
if Actor had credential C, would action be authorized under rule set K?
```

Pressure: state/credential alteration with institution fixed.

## Case I2 — institutional rule change

```text
if rule K were replaced by K', would the same action be authorized?
```

Pressure: constitutive rule change; downstream status meaning may change.

## Case A1 — Agent action change

```text
if Agent chose action a' given the same observation/context, what outcome would follow?
```

Pressure: action token altered, policy potentially held fixed.

## Case A2 — Agent policy change

```text
if policy π were π', what trajectory would follow across future states?
```

Pressure: mechanism/strategy change, not one action.

## Case A3 — model/provider change

```text
if the Agent used model/provider M' under the same task/context, what would happen?
```

Pressure: implementation/mechanism change plus stochastic/coupling problem; `same random seed` may be meaningless across providers.

## Case Q1 — observational probability

```text
among observed X=x cases, what is distribution of Y?
```

Not a counterfactual by itself.

## Case Q2 — intervention probability

```text
if population were assigned X=x, what is distribution of Y?
```

Pressure: interventional distribution.

## Case Q3 — token counterfactual probability

```text
for this token known to have had X=x0 and Y=y0, what would Y have been under x1?
```

Pressure: cross-alternative identity/coupling and abduction.

## Case C1 — simple but-for

```text
if C had not occurred, E would not have occurred
```

Pressure: simple dependence.

## Case C2 — preemption

```text
C produces E; backup B would have produced E if C had not
```

Pressure: simple but-for fails while causal discrimination remains needed.

## Case O1 — omission

```text
if operator had performed required action, failure would have been avoided
```

Pressure: norm/duty/available-action background can matter to attribution.

### Matched-set result

No single untyped operation:

```text
change A; hold everything else fixed
```

can represent all cases without hiding substantial domain-specific choices.

# 28. Circularity inventory

The largest danger is not circularity itself but **unacknowledged reductive circularity**.

## 28.1 Law ↔ counterfactual

```text
laws determine relevant counterfactuals
counterfactual support helps characterize laws
```

This can be explanatory interdependence, but not a clean reduction in both directions.

## 28.2 Disposition ↔ counterfactual

```text

```

Masks, finks and antidotes block simplistic conditional reduction.

## 28.3 Cause ↔ counterfactual

```text

```

Preemption shows simple dependence is insufficient.

## 28.4 Cause ↔ intervention

An `appropriate intervention` can be defined partly by excluding causal side paths, reusing causal vocabulary.

## 28.5 Similarity ↔ counterfactual judgment

If similarity weights are tuned by the very judgments the semantics is meant to explain, similarity may become a redescription rather than an independent reduction.

## 28.6 Identity ↔ selection

Which alternative contains `the same object` can depend on a chosen persistence/constitution theory, while persistence intuitions are themselves often tested counterfactually.

## 28.7 Probability/chance ↔ counterfactual

Chance can be used to evaluate counterfactuals; counterfactual stability can in turn be invoked in interpreting chance-generating setup/mechanism structure.

# 31. Strongest results of WDF2-A

## Result A — a counterfactual is structured deviation, not generic possibility

The minimal common role is an antecedent-indexed evaluation under some constrained departure from an anchor.

## Result B — alteration and invariance are dual

Every alteration implicitly defines a question about what is preserved. The same surface antecedent can encode different counterfactuals depending on preservation profile.

```text
Alteration without invariance = under-specified.
Invariance without alteration = no counterfactual contrast.
```

## Result C — `hold all else fixed` is generally impossible or wrong

Some facts must be allowed to change as consequences; some relations/rules must remain fixed; others are the target of alteration.

## Result D — rule/mechanism/model changes form a structural-surgery ladder

```text
value assignment
< mechanism/policy replacement
< constitutive rule change
< model/boundary revision
< nomological change
```

This is not a metaphysical hierarchy; it is increasing pressure on what `same background` can mean.

## Result E — identity/correspondence is not optional in token-level claims

The phrase `this same X would have ...` imports a domain-specific persistence/correspondence theory.

## Result F — probabilistic counterfactuals add a coupling problem

A probability over separate alternatives does not by itself determine how actuality and counterfactual outcomes for the `same` unit are paired.

## Result G — counterfactual semantics cannot be selected fairly before matched alteration/invariance tests

The immediate next residual is therefore not `Which theory wins?` but:

> **Can candidate architectures preserve the correct alteration, invariance and identity structure across matched cases while changing only one dimension at a time?**
